# Лабораторная работа 1 — последовательная версия

Архитектура, методика эксперимента, генерация данных, замер, верификация и агрегация описаны в [корневом README](../../README.md).

## 1. Цель работы

Задача — реализовать и измерить однопоточную версию программы для синтетического перебора хешей паролей, проверить корректность результатов на разных размерах данных с помощью отдельного инструмента и получить опорные показатели производительности, которые пригодятся в следующих лабораторных работах.

## 2. Алгоритм

Единственный поток обходит весь набор данных подряд:

```cpp
CandidateCounter counter(charset, password_length, range_begin);
stopwatch.start();

for (index = range_begin; index < range_end; ++index)
{
    password = counter.password();
    hash = hash_password(salt, password, iterations);

    if (id = targets.find(hash))
    {
        matches.push_back({id, password, hash});
    }

    counter.advance();
}

time_seconds = stopwatch.elapsed_seconds();
```

Алгоритм принимает алфавит, длину пароля и начальный индекс перебора.

В цикле `for` проходится весь диапазон кандидатов, для каждого индекса генерируется пароль, затем вычисляется его хеш с солью и заданным числом итераций.

Если хеш совпадает с целевым, найденные `id`, `password` и `hash` записываются в файл результатов (`results/seq/results.jsonl`).

Сложность алгоритма — O(N), так как каждый кандидат обрабатывается один раз, а стоимость хеширования одного кандидата не зависит от размера диапазона.

## 3. Результаты

Все прогоны выполнялись на ноутбуке Lenovo IdeaPad 5 Pro 14ACN6 (8/16 GB) с операционной системой Arch Linux и повторялись неоднократно, чтобы исключить аномальные выбросы.

Все 13 прогонов на разных объёмах данных прошли верификацию: 16/16 совпадений с `expected.jsonl`.

## 5. Выводы

1. Последовательная реализация программы корректна: все 13 прогонов прошли верификацию, найдено 16/16 паролей, совпадающих с эталоном. Также получен дополнительный результат — кросс-валидация собственной реализации SHA-256 на C++ против Python `hashlib`, подтверждающая корректность собственной реализации.

2. Экспериментально подтверждена линейная сложность O(N): среднее `T(2N)/T(N) ≈ 2,00`, а пропускная способность не деградирует с ростом размера задачи.

3. Базовый уровень производительности — **≈0,27–0,28 млн канд/сек** (~3,6 мксек на кандидата) на одном потоке. Это опорная точка для последующих лабораторных работ. Ускорение на OpenMP/MPI/CUDA будет оцениваться относительно этого значения.
