## Суть лабораторных работ

Программа перебирает диапазон индексов кандидатов, вычисляет `SHA256(salt + password)` и сопоставляет результат со списком целевых хешей.

1. преобразует целочисленный индекс в пароль по алфавиту;
2. вычисляет хеш;
3. ищет хеш в словаре из 16 целевых хешей;
4. фиксирует найденные совпадения и время вычислительного цикла.

- `src/audit.hpp` и `src/sha256.hpp` содержат всю логику: разбор конфигурации, индекс целей, счётчик кандидатов, запись результата, секундомер и собственную реализацию SHA‑256.
- каждый бэкенд отвечает только за способ перебора диапазона: последовательный цикл, потоки, процессы или GPU.

Все бэкенды выдают идентичные результаты (одни и те же найденные пароли/хеши), а различия в производительности обусловлены исключительно способом параллелизма.

## Методика эксперимента

### Данные

Для каждого кода размера `N` создаётся каталог `data/size_N/` с `range_end = N · 100 000`:

| Код размера | Число кандидатов |     | Код размера | Число кандидатов |
| ----------: | ---------------: | --- | ----------: | ---------------: |
|           1 |          100 000 |     |          64 |        6 400 000 |
|           2 |          200 000 |     |         128 |       12 800 000 |
|           4 |          400 000 |     |         256 |       25 600 000 |
|           8 |          800 000 |     |         512 |       51 200 000 |
|          16 |        1 600 000 |     |        1024 |      102 400 000 |
|          32 |        3 200 000 |     |        2048 |      204 800 000 |
|             |                  |     |        4096 |      409 600 000 |

Состав каталога `data/size_N/`:

- `config.json` — параметры задачи;
- `targets.jsonl` — 16 целевых хешей;
- `expected.jsonl` — эталонные данные.

### Замер и результат

Замеряется основной вычислительный цикл (перебор, хеширование, сравнение) по монотонным часам `steady_clock`, чтение входа и запись результата в замер не входят. Каждый прогон пишет `results/$(BACKEND)/size_N.json`

### Верификация

Сразу после каждого прогона `scripts/verify_results.py` проверяет:

- полноту перебора: `candidates_checked == range_end − range_begin`;
- точное совпадение множества совпадений с эталоном: те же `id`, `password`, `hash`, без дубликатов, пропусков и лишних записей.

Вывод — `VERIFICATION OK` / `VERIFICATION FAILED`.

## Требования

- **Инструментарий C++:** CMake ≥ 4.2, Ninja, компилятор GCC или Clang;
- **vcpkg** с выставленной переменной окружения `VCPKG_ROOT`;
- **Python 3.10+**, утилита `make`;
- Python-пакет `matplotlib >= 3.11`.

## Быстрый старт

### Лабоработрная работа 1 — последовательная версия

```bash
make generate_data                           # 1. датасеты data/size_* для всех размеров
make build                                   # 2. сборка бинарника (при первом запуске — авто-configure)
make start_small    BACKEND=seq LAB=lab_01   # 3a. быстрый прогон + верификация (размеры 1–32)
make start_all      BACKEND=seq LAB=lab_01   # 3b. либо полный прогон (размеры 1–4096)
make generate_plots BACKEND=seq LAB=lab_01   # 4. results.csv + графики в reports/lab_01/figures
```
