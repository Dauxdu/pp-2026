# Лабораторные работы по параллельному программированию

Подробности и результаты конкретной лабораторной работы приведены в её собственном отчёте:

- [**Лабораторная работа 1**](reports/lab_01/README.md) — последовательная версия.
- [**Лабораторная работа 2**](reports/lab_02/README.md) — параллельная версия на OpenMP.

## О чём репозиторий

Необходимо распараллелить вычислительную задачу с использованием открытых стандартов параллельного программирования на языке C/C++. Для этого нужно провести серию тестирований: в первой лабораторной работе — последовательно, во второй — с помощью стандарта OpenMP, в третьей — с использованием интерфейса передачи сообщений MPI и запустить её на суперкомпьютере «Королёв», в четвёртой — с использованием CUDA-ядер.

Тема распараллеливания — **аудит синтетических хешей паролей.**
Программа перебирает диапазон целочисленных индексов, каждый из которых преобразуется в пароль фиксированной длины по заданному алфавиту, затем вычисляет `SHA256(salt + password)` и проверяет полученный хеш по списку из 16 заранее известных «целевых» хешей.

Это симуляция настоящего брутфорса паролей при утечке какой-либо базы данных, где пароли хранятся в виде SHA-256 рядом с солью.

## Архитектура

Вся логика работы всех бекендов находится в `src/sha256.hpp` и `src/audit.hpp`.
В них реализуются алгоритм хеширования SHA-256, чтение `config.json`, индекс целевых хешей, преобразование индекса в пароль по алфавиту, разбиение диапазона на части для параллельной обработки и секундомер.

В `src/<backend>/main.cpp` находится реализация конкретного бекенда, отвечающая только за способ перебора хешей.

Все бекенды на одних и тех же входных данных обязаны находить одни и те же 16 паролей — меняется только время работы.

## Методика эксперимента

Каждый прогон бекенда выполнялся неоднократно, чтобы снизить влияние случайных погрешностей операционной системы и внешних условий. В репозиторий попадает усреднённый достоверный результат.

### Данные

Для кода размера `N` генератор `scripts/generate_data.py` создаёт набор данных в `data/size_N/` с числом кандидатов `N · 100 000`.
В одном наборе размера `N` находятся:

- `config.json` — параметры задачи (алфавит, длина пароля, соль, диапазон);
- `targets.jsonl` — `id` + `hash`;
- `expected.jsonl` — `id`, `index`, `password`, `hash`; данные посчитаны отдельно с помощью Python.

### Замер

Секундомер включается непосредственно перед основным циклом перебора и выключается сразу после его завершения. Чтение конфигурации и запись результата в замер не входят.

### Верификация

После записи результатов выполняется скрипт `scripts/verify_results.py`, который после каждого прогона сверяет количество ожидаемых и полученных целей, полноту и корректность результатов, а также совпадение с данными из файла `expected.jsonl`.
В зависимости от результата он выводит `VERIFICATION OK` или `VERIFICATION FAILED`.

### Агрегация

Следующий шаг — сбор полученных данных с помощью скрипта `scripts/generate_plots.py`, который читает `results.jsonl`, записывает данные в `results.csv` и строит графики в `reports/lab_XX/figures/`.

Конвертация из JSONL в CSV необходима как для упрощения построения графиков, так и для дальнейшего ручного анализа, если потребуется.

## Требования

- CMake ≥ 4.2, Ninja, компилятор GCC или Clang;
- vcpkg с переменной окружения `VCPKG_ROOT`;
- Python 3.10+, `make`;
- Python-пакет `matplotlib`.

## Подготовка и быстрый старт

```bash
python -m venv .venv
source .venv/bin/activate        # Linux / macOS
# .venv\Scripts\Activate.ps1     # Windows (PowerShell)

pip install --upgrade pip
pip install -r requirements.txt
```

После настройки окружения необходимо создать файл `.env` и указать в нём желаемые переменные для запуска теста.
Пример приведён в `.env.example`.

```bash
make build
make data
make start
make plots
```

Количество ядер и потоков передаётся в собранный исполняемый файл флагами `--cores` и `--threads`.
